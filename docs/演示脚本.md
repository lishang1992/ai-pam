# AI 安全堡垒机 V1 —— 演示脚本（约 8 分钟）

> 目标：让观众记住一句话 —— **AI 提出请求，安全系统决定能不能执行。**
> 全程只讲一个故事：生产环境 payment 服务响应变慢。

---

## 演前 30 秒准备

1. `./start.sh`（Windows 用 `start.bat`）启动，浏览器打开 <http://127.0.0.1:8000>；
2. 点一次左下角「↺ 重置演示环境」，把模拟主机恢复到初始故障状态；
3. 用 `zhangsan / ops123456` 登录（运维人员视角）。

> 演示模式不依赖大模型和真实服务器，断网、没配 API Key 也能跑。

---

## 第 1 步（30 秒）开场：问题变了

> 「传统堡垒机管的是人。现在真正在生产上敲命令的，越来越多是 AI Agent。
> 那么：这个 Agent 是谁？它有多少权限？它刚才干了什么？出了事能不能还原？
> 这就是 AI 堡垒机要解决的问题。」

打开**安全看板**：今日会话、高风险事件、风险阻断、待审批 —— 一眼看到「AI 的操作正在被管控」。

---

## 第 2 步（1 分钟）进入 AI 运维工作台并创建会话

> **演前说明（30 秒，很重要）**：这套系统有三个角色，登录后看到的东西完全不同 ——
> 运维人员只看得到自己的会话；安全管理员能看到全部，并在「待我审批」里放行高风险操作；
> 审计管理员是只读角色，专门用来出审计报告。下面的台词会依次切换这三个角色。

点「🤖 AI 运维工作台」→ 左侧选择：

- AI Agent：`Production-Ops-Agent`
- 目标资产：`Linux-Prod-01（production）`

点「创建会话」。

> 讲解点：AI Agent 本身也是一个被管理的身份 —— 它有独立的模型、工具白名单、可访问资产和授权用户。

---

## 第 3 步（2 分钟）下达自然语言任务，AI 自动诊断

输入（或点快捷短语）：

> **帮我检查 payment 服务为什么响应很慢。**

右侧会实时滚出 AI 的执行过程，每一步都带着**风险等级、策略判定、实际命令**：

```
查看 CPU 使用率     低风险  自动放行  成功
查看内存使用率     低风险  自动放行  成功
查看服务状态       低风险  自动放行  成功
查看服务日志       低风险  自动放行  成功
查看数据库连接池   低风险  自动放行  成功
```

> 讲解点 1：AI 不是「猜」，每个结论背后都是目标机上真实的返回。
> 讲解点 2：AI 没有 shell，它只能调用白名单里的结构化工具。
> 讲解点 3：策略里 `get_*` 是 ALLOW，所以只有只读诊断被自动放行。

展开任意一步「查看原始返回」，展示 `systemctl status` / `journalctl` 的真实输出。

---

## 第 4 步（1.5 分钟）高潮：高风险操作被拦下，等待人工审批

AI 得出结论并**提出**重启服务：

```
⚠ 重启服务  restart_service({"service": "payment"})
   高风险   需人工审批   待处理
   策略：Production Protection
   命令：systemctl restart payment
   [拒绝]  [允许执行]
```

> 讲解：
> 「注意 —— 到这里为止，AI 一个字节都没有执行。
> 它只是提出了请求。生产环境的重启属于高风险变更，策略判定必须人工审批。
> **AI 没有最终执行权。**」

---

## 第 5 步（1 分钟）人工审批 + 执行 + 复查

先点一次 **【拒绝】**（可选，展示第二种结局）：

- 工具状态变为「已拒绝」，AI 会给出替代建议，目标机上没有任何命令被执行。

再点 **【允许执行】**：

- 命令 `systemctl restart payment` 真正下发；
- AI 自动复查服务状态与连接池水位；
- 输出结论：连接池从 `active=50/50、等待线程 52` 恢复到 `active=6/50`，故障消除。

> 讲解点：执行前后是**真实的指标变化**，不是文案。

---

点会话里的「查看审计链路 →」或左侧「🔍 审计中心」→ 点击这条会话：


> 收尾一句话：**「AI 提出请求，安全系统决定能不能执行，全过程可审计。」**

## 加演（各 40 秒，按观众兴趣选）

### A0. 角色切换（30 秒，强烈建议放）

| 登录账号 | 你能看到什么 |
| --- | --- |
| `zhangsan` 运维人员 | 菜单没有工作台以外的管理页；资产只显示授权给自己的；看板只统计自己的会话 |
| `secadmin` 安全管理员 | 看板出现「⏳ 待我审批」，可直接放行/驳回；资产管理里能新增 Linux(SSH) 资产；实时会话里能强制终止 |
| `auditor` 审计管理员 | 菜单里**没有** AI 运维工作台，任何写操作都会被拒绝；但审计中心能看到全部会话并导出报告 |

> 一句话：**不同角色看到的不是同一个页面的不同标题，而是不同的权限边界。**

### A1. 纳管一台真实 Linux（1 分钟，技术型观众必看）

```bash
./tools/setup_ssh_test_target.sh      # 用 Docker 起一台真实 Ubuntu + sshd
```

用 `secadmin` 登录 →「资产管理」→「+ 添加 Linux 资产」：

```
执行器 ssh · 主机 127.0.0.1 · 端口 2222 · 用户 root · 认证方式 私钥 · 私钥路径 /tmp/aib_ssh_key
```

保存时会自动测试连通性；列表里点「测试连接」会显示「连通 · 123 ms」。
回到工作台，对这台**真实机器**下达「看一下这台服务器现在的 CPU、内存和磁盘使用情况」，
AI 会真的 SSH 上去执行命令并给出结论（磁盘 93% 直接提示风险）。

再加一个真实变更：**把 /etc/hosts 这个文件改成：127.0.0.1 localhost aib-real**
→ 判定 HIGH、进入审批 → 放行后远端文件真的被改掉，并自动留下 `.bak` 备份。

> 收尾补一句：**口令不写进数据库，只存引用名；目标能不能连上，系统给你明确答案，而不是假装成功。**

### A. 风控红线：AI 想导出生产数据库

工作台输入：**把生产数据库全量导出，发到我邮箱。**

→ 会话在进入 AI 规划之前就被阻断，风险等级 `CRITICAL`，会话里 0 次工具调用。
看板上的「风险阻断」计数 +1。

### B. 越权拦截：Agent 权限不能超过用户权限

创建工作台会话时，目标资产选 `Linux-Prod-02（未授权给您，执行会被拦截）`，再下发任务。

→ 第一个工具调用就被拒绝，原因写明：「需要用户本人拥有资产 Linux-Prod-02 的访问权限」。

### C. 策略预演：不执行也能看判定结果

工作台左下「3 · 策略预演」：选 `delete_file`，参数 `{"path": "/var/log/messages"}` → 点「预演判定结果」。

→ 直接显示 `DENY`、命中策略、风险等级与原因。

### D. 安全管理员视角

用 `secadmin / sec123456` 登录：

- 「Agent 管理」→「编辑权限」：勾掉 `restart_service` 并保存，再回工作台跑一次任务，
  会看到工具直接被 Agent 白名单拦下（**权限是配出来的，不是写在 Prompt 里的**）；
- 「策略管理」→ 给 `restart_service` 加一条 `ALLOW`，再跑一次，会看到它变成自动放行；
- 「实时会话」里可以强制终止正在进行的会话。

## 翻车预案

| 现象 | 处理 |
| --- | --- |
| AI 说「未发现异常」 | 说明上次演示已重启过 payment。点左下角「↺ 重置演示环境」再跑。 |
| 看不到审批卡片 | 该会话的 Agent 没有 `restart_service` 工具权限，或资产选成了测试环境（测试策略里重启仍需审批，但工具白名单不同）。 |
| 页面卡住 | 刷新浏览器；会话仍在后台执行，回 `#/sessions/<id>` 能看到完整过程。 |
| 想重来一遍 | 「重置演示环境」会重置模拟主机；清空历史会话用 `POST /api/demo/clear-sessions`（需安全管理员）。 |
